# FinGrowth Multi-Agent

基于多智能体协作与反思机制的金融客户经营系统。

## 架构
Planner Agent → Analyst Agent → Copywriter Agent → Compliance Agent
（Compliance 不通过时触发反思循环，自动打回 Copywriter 重写，最多3轮）

## 关键设计
- 评分分层采用规则引擎（可解释、可审计），不依赖AI黑盒
- 每个Agent有独立角色Prompt与行为边界
- 合规硬约束同时存在于Prompt层与检查层
- 客户数据为脱敏模拟样本（50条），市场数据来自公开接口
- 跟进记录底表记录客户反馈和意向变化，形成数据闭环
- 前后台分离架构：前端负责单点交互，后台负责批量运行

## 🔐 数据安全与合规声明
- 本项目为个人技术验证项目，**不使用任何真实金融机构的客户数据**。
- 所有客户样本数据均通过 `make_data.py` 基于**公开业务常识和统计学逻辑**合成，仅用于验证系统架构。
- 真实落地时，需在满足《个人信息保护法》和金融监管要求的前提下，进行严格的脱敏、加密和权限隔离，方可接入机构 CRM 数据。

## ⚠️ 当前项目的局限性与未来改进
### 1. 数据层面
- **当前**：使用 `random.seed(42)` 生成了50条模拟客户数据。
- **改进**：真实落地需替换为机构 CRM 数据（需脱敏），并引入 PostgreSQL 数据库。

### 2. 架构层面
- **当前**：基于 Streamlit 单体架构，顺序调用 LLM API。
- **改进**：引入 LangGraph 或 AutoGen 编排框架，实现真正的状态机、记忆机制和并行工具调用。

### 3. 合规审核的循环论证风险
- **当前**：Copywriter 和 Compliance 使用同一底座模型（glm-4-flash），存在“自己审自己”的循环论证风险。
- **改进**：引入不同底座模型（如 DeepSeek + 智谱双盲审），或专门训练一个基于金融监管规则的轻量级分类模型（BERT）。

### 4. 反思机制的有效性验证
- **当前**：反思循环的上限硬编码为3轮，缺乏统计学验证。
- **改进**：需要在大规模真实话术数据集上做 A/B 测试，统计“第1轮通过率”、“第2轮修正通过率”和“最终人工复核率”。

### 5. 成本与限流
- **当前**：`batch_run.py` 使用 `time.sleep(2)` 防止限流。
- **改进**：引入 API 网关和令牌桶限流算法，结合重试机制（Retry with Backoff）。
